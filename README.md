## Учётные данные администратора (задание 4)

- Логин: `hotel123`
- Пароль: `adminHotel`

## Запуск с базой данных (PHP + MySQL)

1. Создать БД и таблицы:

```bash
mysql -u root -p < site/schema.sql
mysql -u root -p < site/seed.sql
```

2. Положить папку `site/` в корень веб-сервера (DocumentRoot), чтобы
   сайт был доступен по адресу `http://localhost/`.

3. При необходимости указать реквизиты подключения к MySQL в
   `site/lib/config.php` (по умолчанию: хост `127.0.0.1`, БД `hotel`,
   пользователь `root`, пароль `root`).

4. Открыть `http://localhost/`.

## Что реализовано

### Задание 1 — диаграммы прецедентов и классов
- Use Case: Гость → просмотр, поиск, фильтрация, бронирование;
  Администратор → управление каталогом, модерация заявок.
- Class: Номер, ЗаявкаНаБронирование, СтатусЗаявки, КатегорияНомера,
  Пользователь → Гость/Администратор, связи и кратности.

### Задание 2 — прототипы
- Главная (шапка: название + слоган; подвал: контакты).
- Каталог: 6 номеров, фильтр по категории, цене, местам,
  кнопки «Применить»/«Сбросить фильтр», «Забронировать».
- Бронирование: поля с валидацией и сообщением об успехе.

### Задание 3 — сайт
- Гость: просмотр каталога, серверная фильтрация, бронирование.
- Администратор: модерация заявок (изменение статуса).
- Вся валидация и фильтрация — на сервере.
- Защита: PDO prepared statements (SQL-инъекции), htmlspecialchars (XSS),
  CSRF-токены, ограничения длины и паттерны полей.

### Задание 4 — бронирование по датам + панель
- Дата заезда — не раньше текущей, выезд позже заезда.
- Период номера с «Одобренной» бронью недоступен (проверка на сервере,
  блокировка периода + календарные подсказки на клиенте).
- Панель управления: вход по hotel123/adminHotel, список заявок,
  одобрить / отклонить / удалить.

## Примечания по развёртыванию
- Для пересборки диаграмм из `.puml` используется PlantUML:
  `java -jar plantuml.jar task1_diagrams/*.puml`
- Хэш пароля администратора в `schema.sql` соответствует паролю
  `adminHotel` (проверено `password_verify`).
- Деплой на GitHub Pages выполняется через `.github/workflows/pages.yml`.
